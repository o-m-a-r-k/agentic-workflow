# I-180: Gate-order approval repeats after workflow-only base merge and fresh reviewer

- **Class:** engine
- **Fixed in:** 0.7.23
- **Test:** `scenarios/questions.test.mjs`

## Failure

Owner approved batch A1 to run the missing support proof after honest reviewer left evidence finding open. Master had moved only planner model configuration; owner merged base and fresh review found0new issues while preserving original missing-proof finding. Same gate command/reason now opens A2 solely because latest reviewer identity changed. Preserve explicit gate-order authorization when obligations and substantive reason remain unchanged, or merge/review before presenting the decision, without transferring approvals across changed risk or weakened tests.

## Fix

The gate-order approval is keyed by the ticket's own change (patch ids without blob ids and hunk line numbers) and by what the order still owes, so a base merge that leaves both alone keeps the person's answer; review coverage uses the same stable change.
