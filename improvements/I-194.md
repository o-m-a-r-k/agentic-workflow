# I-194: Batch admission requirement needs actionable guidance

- **Class:** docs
- **Fixed in:** 0.7.29
- **Test:** `scenarios/batch-validation.test.mjs`

## Failure

Batch create refuses attempts not admitted with --defer-heavy and prints no repair route; entry help does not describe this requirement. Three unimplemented quick-lane TS attempts need owner-authorized restart. Make batch admission guidance explicit.

## Fix

The batch:not-deferred refusal gives the route (deliver an implemented attempt alone; abandon and re-admit an unimplemented one with --defer-heavy, keeping its lane), and entry and batch help say how a member is admitted.
