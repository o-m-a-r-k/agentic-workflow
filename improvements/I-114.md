# I-114: A planner whose output cannot be read leaves no refusal for the next planner

- **Class:** engine
- **Fixed in:** 0.7.4
- **Test:** `scenarios/fix-074-lifecycle.test.mjs` (a planner output that cannot be read as a plan is recorded with the refusal)

## Failure

When wf plan --from-agent cannot find or parse the planner's YAML, the refusal is not recorded, so the next planner's bundle does not carry it (validation refusals are carried since 0.7.0).

## Fix

wf plan records a planner transcript with no fenced YAML block, YAML that does not parse and a plan file that does not parse as a plan refusal (plan.refused), so the next planner's bundle carries it; an owner's mistake still records nothing
