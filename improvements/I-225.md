# I-225: pushedRange marks a fast-forwarded or rebased base commit as the attempt's own

- **Class:** engine
- **Fixed in:** 0.7.33
- **Test:** `scenarios/deadlocks-0732.test.mjs`

## Failure

Fable's re-check of 0.7.32: after a hand push, another ticket landing on main and git merge --ff-only in the worktree, the other ticket's commit is merged:false and its file is listed in delta.changed as this attempt's. Fail-safe, but unlabelled; say in the instruction that an unmarked commit is not proven the ticket's, or detect commits already on the fetched base by patch id.

## Fix

A pushed-range commit is marked the base's only by the reflog action that first brought it into the worktree (merge, pull, rebase, reset, checkout, not the first entry) or by patch id; never by timestamps.
