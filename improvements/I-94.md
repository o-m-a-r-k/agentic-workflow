# I-94: Validate a visual evidence route before freezing UI criteria

- **Class:** engine
- **Fixed in:** 0.7.0
- **Test:** `scenarios/capture-route.test.mjs` (captures made by hand on the committed tree)

## Failure

<ticket> froze required English/Arabic desktop/narrow screenshot criteria, but the admission-pinned adapter has no screenshot collector. The full gate passed without images, and acceptance only discovered the missing route afterwards. Check for a configured capture path during planning, and provide a supported tree-bound import route for owner-produced local browser captures instead of requiring a late criteria-reference workaround.

## Fix

A criterion that names screenshots while no gate step can collect any is warned about at wf plan, wf criteria amend, wf status and wf resume; wf captures import brings in captures made by hand on the committed tree as the gate's screenshots for that tree, read once without following a link and recorded and protected by wf.
