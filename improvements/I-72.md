# I-72: Scope authority ignores a valid earlier answer in a combined desktop reply

- **Class:** engine
- **Retired in:** 0.7.0
- **Refusals recorded:** none named

## Failure

Codex desktop emitted one genuine bound question-reply envelope with two submitted answers: scope expansion first and local inventory commit second. codexOwnerReplies correctly exposes multiple answers, but ownerAuthority(scopeChoice) uses humans.slice(-1), selecting the unrelated commit answer and rejecting the valid unspent scope answer from the same latest host line. Existing D1 single-answer UI receipt worked. Preserve one-use original host-line spend and latest-human-turn protections while selecting the bound scope answer within the latest combined host turn; do not require duplicate human authorization or forged transcripts.

## Why it was retired

Obsolete: 0.7.0 deleted the owner-reply grammar (ownerAuthority); no engine path reads a person's chat turn, so a combined reply cannot be misread.
