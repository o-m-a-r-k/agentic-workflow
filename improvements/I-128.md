# I-128: handoff stop records stopped but leaves native Codex child alive

- **Class:** engine
- **Fixed in:** 0.7.9
- **Test:** `scenarios/handoff-stop-tree.test.mjs`

## Failure

A planner launched on Codex: `wf handoff stop` reported it stopped, but the `wf` wrapper and its `codex exec` child kept running and kept emitting progress. They had to be ended by hand with SIGTERM, after which `ps` showed both gone and the foreground run returned interrupted. Asked for: keep the stopped record, but make sure the launched process tree actually stops, and verify it.

## Fix

wf handoff stop and an interrupted foreground run end the role's whole process tree (group, descendants, children that left the group), escalate to SIGKILL, record stopped only once it is gone, say what could not be signalled, and leave a pid the system gave to another process alone.
