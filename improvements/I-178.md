# I-178: Synthetic delivery batch incorrectly requests tracker implementing lifecycle

- **Class:** engine
- **Fixed in:** 0.7.23
- **Test:** `scenarios/fix-0721.test.mjs`

## Failure

Version0.7.21 resume requests implementing status/readback for BATCH-<ticket>. The batch has no independent tracker ticket; its accepted members both identify <ticket>. Current real ticket was read, set In progress and completely read back. Batch tracker record refuses raw real ticket because capture is <ticket> not BATCH-<ticket>; both members refuse because no implementing action is pending. Synthetic batches should route lifecycle to real members and retain batch no-comment semantics.

## Fix

A batch, and an attempt that owns its item, owes no tracker step: emitTrackerEvent emits nothing without a ticket, and the reducer skips tracker.pending an older engine queued for them.
