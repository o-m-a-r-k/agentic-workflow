# I-212: Deferred heavy steps hide a ticket's own e2e specs until the batch gate

- **Class:** engine
- **Fixed in:** 0.7.28
- **Test:** `scenarios/fix-0728b.test.mjs`

## Failure

With --defer-heavy, no heavy step ran on any member; a ticket's own new e2e spec first ran at hour 28 in the batch gate, and screenshots were inspected by no reviewer before then. The batch gate then failed five times (158 minutes) on pre-existing flaky specs the batch does not touch, each turned into a repair round. Goal: at member acceptance run the heavy specs the ticket itself adds or edits even when heavy steps are deferred; offer the person one reserved decision to quarantine a pre-existing failing suite the delivery does not touch, instead of repair rounds (relates to I-134).

## Fix

A defer-heavy batch member runs the spec files it adds or edits; wf gate quarantine asks the person one override question for a failing suite whose test file the delivery does not edit, saying what was and was not checked, and the next step after a failed gate names it.
