# I-19: Scope fences must never block a fix: a fix that needs another component or repo extends the attempt

- **Class:** template
- **Fixed in:** 0.4.4
- **Test:** `scenarios/discovered.test.mjs` (I-19: a discovered fix adds a repo)

## Failure

The planner froze a criterion that forbade any <project> change in a <project> ticket. A defect found during the ticket (page-only totals under a new pager) needed an additive <project> change, and the only way through was an owner amendment framed as an exception. A fix that spans components is ordinary work, not an exception. The planner template and engine should (1) never write blanket 'no X change' criteria as hard limits; state the invariant instead (the contract seam stays matched, existing fields, permissions and tenant isolation unchanged), (2) let a discovered fix add a repo and work items to the attempt in one owner step, with the cross-component contract seam reviewed on both sides, and (3) have the reviewer and the lifecycle docs treat a scope fence that blocks a fix as a criteria defect to be corrected, never as a reason to defer or to ship a cosmetic workaround.

## Fix

The planner template states invariants (the contract seam stays matched; existing fields, permissions and tenant isolation unchanged) instead of blanket no-change criteria and no longer plans fixes as follow-ups. wf criteria amend --add-repo R adds a repo's worktree and its work item to the running attempt in one owner step; the reviewer bundle lists added repos and the closure judges each contract seam on both sides (producer and consumer file:line), refused without. Reviewer and lifecycle docs treat a scope fence that blocks a fix as a criteria defect, never a reason to defer or to ship a cosmetic workaround.
