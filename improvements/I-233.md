# I-233: A base merge forced by the gate reopens review, so 'reconcile the base once' cannot be followed

- **Class:** engine
- **Fixed in:** 0.7.34
- **Test:** `scenarios/base-merge-classes.test.mjs`

## Failure

The gate refuses a base that moved ('merge the current base before the required gate'); merging the base makes the tree new, which reopens a review round; by the time that review is clean the base has moved again. On one attempt the strategist's correction 'reconcile the base once' could not be followed: the base was merged six times, with eight gate stops, and rounds 18-20 were spent on base and toolchain drift. Find a flow where a base merge that brings in only other work re-reviews only what the merge changed in this attempt's files (or nothing when the merge touches none of them), and the gate runs on the merged tree without another full round.

## Fix

A base merge is classed from git facts (none, context, changed) and owes at most one judgement of what it changed in the ticket; merge once right before the gate; acceptance is re-recorded across merges that left the change alone.
