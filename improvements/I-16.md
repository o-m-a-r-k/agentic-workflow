# I-16: Evidence guard rejects harmless Bash commands that do not touch evidence

- **Class:** guard
- **Fixed in:** 0.4.5
- **Test:** `scenarios/evidence-read.test.mjs` (I-16: the refusal names the matched token and says how to avoid it)

## Failure

An implementer's Bash calls were refused by the evidence guard although none touched the evidence folder; it had to split commands or switch tools. Match only commands that really name the evidence path, and say which token matched when refusing. Note: even prose in an improvement text that names the folder is refused, so the guard also fires on text arguments.

## Fix

The guard's refusal names the token that matched (or the working directory) and says how to avoid it: write 'the evidence folder' in commit messages, echo text and grep patterns; read evidence with the Read tool or the new read-only wf evidence list and wf evidence show; copy screenshots out with wf export screenshots; run each wf command as one plain invocation. Nothing previously refused passes (no tokenizer, no quoting allow-list); wf run is no longer treated as a plain wf invocation. Role texts and the work skill use wf evidence.
