# I-182: Batch handoff caps screenshot inventory before ticket-specific support captures

- **Class:** engine
- **Fixed in:** 0.7.26
- **Test:** `scenarios/delivered-captures.test.mjs`

## Failure

After accepted batch delivery, each member handoff records the first40 broad upstream screenshots (attendance/payroll), excluding all support, loan and timesheet captures from510 verified records. Batch is already done, so narrowing it refuses; member narrowing can only keep existing40 and cannot select the verified ticket-specific hashes. Provide supported ticket-specific selection from the complete verified inventory before the cap, or replacement while member handoff remains pending. Supplemental native ticket-proof images can be attached separately, but engine rendered handoff should not prioritize unrelated upstream captures.

## Fix

A handoff draws from every verified capture: cited by its criteria first, then its own (tagged by attempt or item id), then shared; other tickets captures out; wf delivery list shows all and narrow can add any.
