# I-191: Fix and review rounds work one finding at a time, so a cause that spans places recurs round after round

- **Class:** engine
- **Fixed in:** 0.7.27
- **Test:** `scenarios/recurring-cause.test.mjs`

## Failure

A ticket ran 10+ review rounds where each round found the next place a single wrong assumption lived (pending AED rate treated as invoice-only, built into six places). Fix rounds hand the implementer only the latest finding (repair families labelled by symptom), so it fixes that path's cause, never the shared assumption; a delta reviewer's goal is whether the change fixes what it set out to fix, so a local fix is marked fixed while the cause lives elsewhere; nothing shows the owner that findings across rounds share a cause. An outside root-cause pass found it after the round limit. Needed: fix-round goal = the problem is not found again anywhere (finding history in the bundle, name the assumption and every place relying on it); reviewers judge cause not place (sameCauseAs links, a fix that leaves the cause elsewhere is open); resume surfaces a recurring cause with root-cause guidance. Goals, not new stops.

## Fix

See docs/releases/v0.7.27.md (I-191).
