# I-22: Adapter-fault recovery is tested only for a single-repo standard-lane attempt with nothing recorded as delivered

- **Class:** engine
- **Fixed in:** 0.5.0
- **Test:** `scenarios/adapter-fault.test.mjs`

## Failure

Recovery after a delivery adapter reports an undocumented state is proven only for a single-repo standard-lane attempt whose delivery.repos is empty (abandon, re-enter, git merge --squash the old branch). Untested or unsupported: several repos (an unchanged repo is recorded as skipped first, after which wf abandon refuses), quick-lane attempts (entry with or without --item, planner per roles.planner.lanes), batches, and any attempt with a repo already delivered. The wf abandon refusal does not say whether a repo was delivered or only skipped. Decide the supported recovery per case, make the refusals name the case, and add a scenario for each.

## Fix

Adapter-fault recovery is proven by scenarios for a single repo after wf base merge, the change already merged into the base (acknowledged state), several repos with one delivered, several repos with one skipped (wf abandon now accepted when every recorded repo was skipped; the refusal otherwise names each delivered and skipped repo), the quick lane and a batch (members refused, the batch re-pinned); docs/lifecycle.md 'Recovering from an adapter fault' cites the scenario for every claim.
