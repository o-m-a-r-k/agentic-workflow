# I-27: Order of work: code review rounds run to clean first, then ONE gate, then the evidence review; engine refuses a gate while a review round has open findings, and refuses reviewer handoffs while a gate runs (supersedes the ordering in I-23)

- **Class:** engine
- **Fixed in:** 0.5.0
- **Test:** `scenarios/review-order.test.mjs` (regression: a gate and a reviewer never start side by side, in either order)
- **Commit:** fb57a2b

## Failure

Owner decision after the <ticket> retrospective: review and gate must not run in parallel. Sequence: (1) code review rounds with no gate until a round comes back with no findings; (2) one gate on that tree; (3) the evidence review (screenshots, gate logs) on the gated tree. Reason: any finding after a gate starts makes the gate obsolete (<ticket>: 15 of 16 gates stopped, about 175 of 271 gate minutes discarded), and a gate on an unreviewed tree proves nothing about review. Engine: wf gate refuses (or requires a recorded override reason) while the latest review round of the attempt has open findings or no review round has covered the current tree; wf handoff reviewer refuses while a gate is running on the attempt; wf stop of a gate requires a reason class; the work skill and role texts state the order. This supersedes the part of I-23 that asked for a green gate before a review handoff: the code-review rounds precede the gate, and only the evidence review requires a gate.

## Fix

wf gate refuses until a code-review round on the current tree is clean and no reviewer is at work (--reason records a gate.override); wf handoff reviewer refuses while a gate runs and records its round under the gate lock; bundles mark code-review vs evidence-review; wf resume, skills, roles and docs state the order
