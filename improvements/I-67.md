# I-67: Owner release authorization from Codex question replies is not recognized

- **Class:** engine
- **Fixed in:** 0.5.13
- **Test:** `scenarios/owner-question-reply.test.mjs` (a question reply releases a real held attempt once)
- **Commit:** e1e969a

## Failure

The owner answered release <ticket> through request_user_input_async. wf release refused because the desktop records the human reply in a send_user_message_question_reply wrapper, while owner authority accepts only messages starting with the release phrase. Recognize host-recorded human question replies with exact answer validation, session ownership and one-use spend; never treat arbitrary tool output or relayed agent text as authority. Add a scenario covering this desktop reply and rejection of forged non-human equivalents.

## Fix

Bind submitted desktop question answers to the earlier host question call while preserving original message audit identity and one-use authority safeguards.
