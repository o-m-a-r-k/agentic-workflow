# I-102: Permit audited correction of supplemental validator plugins after review findings

- **Class:** engine
- **Fixed in:** 0.7.0
- **Test:** `scenarios/validation-correction.test.mjs` (a corrected plugin is pinned again)

## Failure

Supplemental validation pins its single-file plugin before independent review. Review can find a defect in that plugin, but registration has no remove, overwrite or repin operation. Fixing and committing the plugin leaves the required gate running the defective old plugin forever. Add a guarded correction path preserving every admission obligation, requiring closed roles, committed descendant inputs, recorded reason, fresh code review and full gate.

## Fix

wf validation correct re-pins a registered supplemental check at a later commit of the adapter repo that descends from its pin, under every obligation of a registration (closed roles, a committed tree, a recorded reason, existing catalogued keys, admitted repos), with both pins in the ledger and a fresh code review and full gate required.
