# I-49: Generated lesson YAML fails repository Prettier formatting contract

- **Class:** engine
- **Fixed in:** 0.7.4
- **Test:** `scenarios/fix-074-lessons.test.mjs` (a generated lesson is laid out for the repository)

## Failure

<ticket> on wf 0.5.6: wf lesson add generated and committed <project>/.workflow/lessons/L-7.yaml and <project>/.workflow/lessons/L-8.yaml. Parent ran each repository node_modules/.bin/prettier --check on its generated lesson file: both exit1 with Code style issues found. Repository style expects single quotes where generator emits double quoted trigger.what text. Current W1 implementer will apply scoped formatting with full parsed YAML equality proof and commits; C12 records lessons and C16 requires whole-tree formatting. Make managed YAML generation respect declared repository formatting or otherwise produce formatting-compatible records without introducing arbitrary command execution or changing lesson semantics. Add a scenario for generated lesson under a project singleQuote formatter contract.

## Fix

A lesson file is laid out for the repository's Prettier config, found statically in Prettier's own order (package.json with a prettier key first, the nearest folder, overrides by path): tabWidth, singleQuote and endOfLine are honoured, printWidth and proseWrap preserve or never are irrelevant because text is never folded, a long text is a literal block under proseWrap always, and recur, set and move keep the layout; a config form that cannot be read stops the search and degrades to Prettier's defaults, an existing file keeping its own layout.
