# I-104: wf run from inside the adapter repo of a multi-repo project took that repo for the project

- **Class:** engine
- **Fixed in:** 0.7.2
- **Test:** `scenarios/delivery.test.mjs` (wf run from inside the adapter repo of a multi-repo project works on the project, not on the repo)

## Failure

A multi-repo project keeps its adapter in one repo and links the project's .workflow to it, the layout wf init makes. Run from any folder inside that repo, wf stopped at the repo's own .workflow folder and treated the repo as the project: wf status listed no open attempts while the project had one, and wf doctor and wf entry failed with '.workflow/ is not inside any listed repo'.

## Fix

findRoot keeps walking up after it finds an adapter: a folder above whose .workflow link leads to that same adapter is the project root, so every command run inside the adapter repo (or any other repo of the project) works on the project.
