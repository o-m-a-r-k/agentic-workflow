# I-154: Validate screenshot references when recording a review

- **Class:** engine
- **Fixed in:** 0.7.29
- **Test:** `scenarios/evidence.test.mjs`

## Failure

A completed evidence review was recorded with twenty comma-separated screenshot hashes in one scalar criterion evidence.ref. Acceptance later rejected the entire string because it is not one collected artifact, after the native reviewer had finished. Validate this reference at review recording so the active reviewer can correct citation structure, and carry formal acceptance refusals into subsequent evidence-review bundles. This is citation validation, not a reason to repeat the merits audit or change protected evidence by hand.

## Fix

wf review runs acceptance's screenshot check in an evidence round, so a joined or glob citation is corrected by the same reviewer; one artifact per evidence entry; every acceptance refusal is handed to the next evidence review.
