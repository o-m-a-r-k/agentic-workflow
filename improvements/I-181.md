# I-181: Abandoning an assembled batch strands its members

- **Class:** engine
- **Fixed in:** 0.7.24
- **Test:** `scenarios/deferral-rule.test.mjs`

## Failure

Abandoning a BATCH-* attempt leaves each member with batchOf pointing at the abandoned batch: wf batch eject then fails (the batch worktree is gone), wf deliver on the member says to deliver the batch instead, and wf batch create refuses members already in a batch, so the members can be neither delivered nor re-batched. Found while fixing I-177 (the batch-fixes stream reproduced it in a scratch scenario). A fix must keep the split guarantee: members a split put together leave the batch only on the person's decision.

## Fix

Abandoning an assembled batch releases its members (batch.ejected on each; one person's question when a split put them together); a member a batch abandoned earlier still points at is ejected with only its own record.
