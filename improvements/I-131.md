# I-131: Scenario runs write refusals into the person's own refusal log

- **Class:** engine
- **Fixed in:** 0.7.9
- **Test:** `scenarios/learning.test.mjs` (scenario processes keep their user-level state to themselves)

## Failure

A scenario that spawns wf with a copy of process.env (state-folders CLI failure test, and others) bypasses the WF_IMPROVEMENTS_DIR the run helper sets, so its refusals land in <path> 138 of 335 entries in one maintainer's log came from temporary scenario projects, and wf refusals and plugin triage read them as real use.

## Fix

scenarios/helpers.mjs gives every scenario process its own temporary improvements folder (the refusal log sits beside it) and config home, so a command spawned with a copy of process.env never writes the person's own state.
