# I-177: Assembled batch cannot own or settle member observation selected for fix

- **Class:** engine
- **Fixed in:** 0.7.23
- **Test:** `scenarios/deferral-rule.test.mjs`

## Failure

<ticket> was accepted with low observation summary_evidence1:F1 pending user A7. Both accepted members assembled into BATCH-<ticket>, then user selected fix now. Scope move to BATCH refuses not in delivery batch despite the id being its batch. Scope fixed requires fix commit on member HEAD, while deliver refuses any member HEAD change after assembly and says eject and re-add. CLI exposes eject but no add; batch create refuses members already in a batch. Need a supported route for batch-owned repair/evidence to settle inherited member observations without dropping obligations or rewriting protected evidence. Product repair can be prepared in batch; member obligation must remain explicit until supported settlement.

## Fix

A member's observation answered fix now after its batch was assembled moves into the batch (wf scope move --sibling <batch>), which must close it before delivery; the member stays locked; an eject that would drop the batch's own commits is refused unless --drop-own-commits records them.
