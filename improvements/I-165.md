# I-165: Use one authoritative work plan after amendments

- **Class:** engine
- **Fixed in:** 0.7.30
- **Test:** `scenarios/fix-0730c.test.mjs`

## Failure

<ticket> amendment6 added explicit C10 calendar localization and a bounded overall repair plan, but W4 implementationPlan/files still carried the older import snapshot. Handoff34 repair listed only blocking F1, omitting user-approved high observationF2; the implementer completed captureF1 only and reported no work left despite amended C10. Owner caught the omission before independent review and synchronized the already-approved plan into W4 in amendment7. Prefer one authoritative plan/reference or synchronized work projections, with visibility of user-directed observation repairs, instead of duplicated stale planning fields or another expensive review loop. No current runtime changes or skipped guarantees are proposed.

## Fix

An amendment that adds a criterion when the plan groups criteria into work items must name the work item that builds it (amend:criterion-no-work), for attempts admitted from 0.7.30.
