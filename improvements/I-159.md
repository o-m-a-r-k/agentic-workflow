# I-159: Hotfix planning added an unrequested notification lifecycle

- **Class:** template
- **Fixed in:** 0.7.30
- **Test:** `scenarios/fix-0730c.test.mjs`

## Failure

In <ticket> the user requested a fast completion-alert hotfix using the existing inbox. The planner initially proposed a new completion ledger, migration, revision updates, backoff delivery and retention tombstones, with a 180-minute estimate. These extra guarantees were not requested. The owner contracted it to the existing import-lock/terminal transaction: one immutable inbox alert per completed processing cycle, with explicit user retries permitted a new alert; no schema or recovery subsystem. Make the quick-lane planner explicitly justify extra lifecycle infrastructure against the requested hotfix outcome and existing durable boundaries before expanding its contract.

## Fix

A plan names what it adds beyond the request in beyondAsked, each with why; wf plan prints it for the person and the owner passes it on.
