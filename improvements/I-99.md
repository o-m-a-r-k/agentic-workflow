# I-99: Lesson recording after accepted-tree repairs must use the task worktree

- **Class:** engine
- **Fixed in:** 0.7.4
- **Test:** `scenarios/fix-074-lessons.test.mjs` (a lesson recorded after the accepted tree moved)

## Failure

After an accepted attempt is adopted and its criteria amended for repairs, lesson add still writes new lesson files into the main checkout. This violates the project pull-only main-checkout rule and repeatedly requires verifying and moving the exact task-owned lesson into the active worktree. Resolve the lesson target from the current open handoff and phase rather than stale acceptance state; add a regression for adopted accepted attempts with criteria amendments.

## Fix

A lesson is committed in the attempt worktree while the attempt's acceptance does not stand (the tree moved past the accepted heads, or an implementer handed after the acceptance is open) and written to the main checkout while the accepted tree is frozen; an implementer left open at acceptance no longer moves the accepted tree, a recurrence at acceptance of the attempt's own lesson leaves no second copy in the main checkout, and a moved lesson's removal is committed in the worktree it left (refused while that tree is accepted).
