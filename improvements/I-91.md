# I-91: Check step ledger contention crashes the runner before final cleanup

- **Class:** engine
- **Fixed in:** 0.7.4
- **Test:** `scenarios/fix-074-gate.test.mjs` (a progress file that cannot be written ends the run)

## Failure

wf check <ticket> run 2026-10-12T14-59-58-748Z-26839 exited1 from an unhandled WfError in the execute job completion append at gate.mjs:740. It had passed <project> typecheck/invariants but had no final result; logs were temporarily unreadable while the evidence transaction was locked. The supported wf check recovery path is being used, with host PID visibility. Serialize or retry completion recording without weakening evidence guards, and guarantee child cleanup on unexpected recording failure.

## Fix

any error that escapes the gate run (scheduler timer or completion callback, a step plugin's timer, an unreadable lease slot) signals every child, frees the run's lease slots and handlers and records the run failed with the error; a lease slot that vanished or cannot be read is waited for
