# I-28: npm run verify is slow: three legs in series, helper-only wf processes, the macOS git shim

- **Class:** other
- **Fixed in:** 0.5.0
- **Test:** `scenarios/compile-cache.test.mjs`

## Failure

The maintainer's verify ran the host leg and both Linux legs one after the other (196s measured, reported as far longer on a busy machine). The suite was bound by CPU and by its longest file: the scripted owner spawned wf resume before every owner-only command and reviewer handoff (595 of 3,750 wf processes), every git call on macOS went through the xcrun shim, and two files of about 55s serial set the floor of each leg.

## Fix

verify runs its three legs in parallel, each with a share of the cores by measured cost, and prints each leg's time (--host-only, --linux-only, --serial); the scripted owner reads the attempt in-process (evidence verified, ledger folded) instead of a wf resume process, with a check mode that compares both; macOS scenarios call the real git instead of the xcrun shim; wf processes share a private per-process compile cache; the two longest files are split. Host leg 81s to about 50s (806 to about 520 CPU seconds), full verify 196s to 113s on the same machine; same tests, same counts plus the compile-cache scenario.
