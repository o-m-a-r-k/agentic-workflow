# I-103: A decision taken on an orphaned attempt reported a missing-worktree failure after it was recorded

- **Class:** engine
- **Fixed in:** 0.7.1
- **Test:** `scenarios/dead-ends.test.mjs` (a decision taken on an orphaned attempt is reported done and points at abandon, not at the missing folder)

## Failure

The person confirmed a reserved decision with wf approve on an attempt whose worktree folder had been removed (the decision to abandon it with an open integration). The choice was recorded, then the command failed with 'worktree missing: ... (git was not run there)' while printing the next step, so the decision read as not taken. wf release failed the same way after lifting a hold. The orphan check guarded only the status and resume lines; every other command computed its next line with git in the missing folder.

## Fix

The orphan check moved from the CLI's status lines into nextDecision, where every next line is decided, before any git call: approve, release and every other command report an orphaned attempt's next step as ORPHANED with its missing paths and the abandon command.
