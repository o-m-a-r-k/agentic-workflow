## v0.4.4

- **Every issue found during a ticket is fixed in it (I-18).**
  - `wf discovered add --summary "..." [--where file:line] [--found-by ID]` records an issue any role finds, inside or outside the criteria. `wf discovered list` shows them; status and resume count the open ones.
  - `wf discovered close D1 --fixed <commit>` needs a commit of this ticket (on the attempt's branch, after its base). `--deferred --decision "<the owner's own words>"` records the owner's decision verbatim; no words, or a role agent named in `--by`, is refused.
  - `wf deliver` refuses while one is open. Deferred entries reach the delivered comment's known limits and the attempt page.
  - The implementer and reviewer bundles list every entry. The closure gives each a verdict (`discovered: [{ id, verdict: fixed|deferred|open, evidence }]`); `wf review` refuses one missing, `wf accept` refuses an `open` verdict and an entry recorded after the round was handed.
  - The implementer, reviewer, planner, work and quick-fix texts say: record every issue, never defer it yourself or call it harmless, and amend the criteria when they block the fix.
  - **The role that found it fixes it.** An implementer fixes what it finds in this attempt, in whatever file it lives in; the work-item brief is never a reason to leave it, and the owner sends it back instead of fixing or relaying it. The one exception, a file another work item is editing at that moment, is recorded with `wf discovered add ... --blocked-by <work item>`; the next step routes it to that work item's implementer.
  - **`wf handoff reviewer` refuses an implementer report that leaves an issue unfixed** ("not fixed", "outside the brief", "out of scope", "follow-up" ...) without naming its discovered entry. The report is read from the implementer's Claude Code transcript; elsewhere nothing is checked.
- **Scope fences never block a fix (I-19).**
  - The planner template no longer writes blanket "no change in X" criteria or plans fixes as follow-ups. It states the invariant instead: the contract seam stays matched; existing fields, permissions and tenant isolation are unchanged.
  - `wf criteria amend --file f --reason "why" --add-repo R` adds a repo to the running attempt in one owner step: its worktree on the attempt's branch from the current base, provisioned as at admission, with the amendment's work item for it. Gate and delivery then cover it like any other repo.
  - The reviewer bundle lists added repos under `addedRepos`. The closure judges each seam on both sides (`seams: [{ repo, verdict: matched|finding, evidence, finding }]`, `matched` citing the producer's and the consumer's file:line). The reviewer and lifecycle docs treat a fence that blocks a fix as a criteria defect, never a reason to defer or to ship a cosmetic workaround.
