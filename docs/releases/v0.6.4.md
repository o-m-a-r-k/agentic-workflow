## 0.6.4 - Group complete flows before assigning review ownership

Related actions assigned to the same reviewer no longer send their common files to integration merely because
the actions have distinct flow queries. Automatic division compares a balanced candidate with an overlap-aware
candidate when necessary. Actual cross-scope dependencies, unassigned flows and unmapped files remain integration-owned.

- I-83: classify ownership after grouping complete recorded flows, including areas without individually exclusive files.
  Three independent features with overlapping actions now divide 72 files into three 24-file scopes.
- Bound optional overlap search by pair contributions, distinct pair allocations, queued pairs and neighbor visits.
  Exhaustion discards the search and retains the balanced candidate under the same efficiency thresholds;
  owner diagnostics report `optimization-budget-exceeded` separately from the division decision.
- Keep consumer, contract and suite query results in ownership analysis. Preserve every failure path and crossing
  interface, and retain integration evidence for unassigned flows and unchanged context.
- New divisions validate exact group-based ownership and full interface coverage. Already frozen version-one
  handoffs retain their recorded assignments and original checks; active reviews are not rewritten.
- Owner diagnostics show workload per scope, separate integration causes, retained internal overlap, and exact
  efficiency thresholds. Inefficient manual divisions warn rather than silently changing the proposed assignment.
  Diagnostics stay outside the blind one-line reviewer start prompt.
- Existing small-change and efficiency thresholds, immutable scoped reports, findings union, source snapshots,
  runtime provenance and code-review/gate/evidence-review order remain enforced.

Regression scenarios cover real shared hubs, unmapped and unassigned dependencies, alias conflicts, empty scopes,
cross-repository contracts and tests, tampered ownership and interfaces, deterministic grouping, threshold boundaries,
legacy handoffs and native scoped/integration launch behavior. Real model review speed and defect recall remain
unbenchmarked; changed-line workload is an estimate rather than a duration prediction.
