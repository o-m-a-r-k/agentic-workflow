## 0.6.6 - Record descriptive scope choices without repeated approval

A genuine desktop scope choice such as "Increase scope and include the responsive fix" now records
the narrow expansion directly. The owner does not need to repeat the same approval as a separate command phrase.

- I-93: accept bounded, explicit and unconditional fix descriptions after the anchored scope question.
- Keep host question binding, latest-reply revocation, one-use authority and finding-set limits intact.
  Conditional choices, conflicting instructions, blanket expansion and forged or replayed replies remain rejected.
- Return canonical scope picker labels and direct agents to put finding descriptions in the question.
- Refused scope decisions explain the missing decision rather than incorrectly requiring magic words.
- Align the CLI package and both host plugin manifests at 0.6.6 so upgrades load the corrected implementation.

Regression scenarios reproduce the descriptive selected option, recommendation suffix, wrong-choice refusal,
pre-question approval, revocation, replay and conditional or conflicting answers. Existing authorization,
scope, adoption and guard scenarios remain required. No decision skips code review, gates or delivery authorization.
