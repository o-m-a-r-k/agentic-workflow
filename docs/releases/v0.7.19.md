## 0.7.19 - A fix made before its record, and no stale copies

- **A defect fixed before it was recorded can be closed.** An implementer fixed a high privacy defect and then recorded it.
  `wf discovered close D3 --fixed <commit>` refused that commit, because it was already in the tree D3 was recorded on, so
  no route could close D3. An independent review had verified the fix, but a reviewer's verdict does not close an entry.
  The owner agent then asked the person to approve changing the workflow itself. Now:
  - closing with a commit made before the record records a claim, at any severity, and creates no question for the
    person;
  - the next reviewer's bundle marks the entry `claimedFixed`, with the commit and what to give;
  - that reviewer's `fixed` verdict closes it, bound to the claimed commit and the reviewer;
  - the verdict counts only when that reviewer's bundle showed the entry and the claimed commit;
  - a review that gives no verdict leaves it open, and `wf resume`, `wf discovered list` and `wf deliver` name the route;
  - when a reviewer already verified the entry (its bundle showed it, in any release), the owner's close with that commit
    closes it at once;
  - a commit named by mistake closes nothing on the owner's word.

  An implementer's own low bookkeeping entry is still reconciled as before (I-139); any other bookkeeping entry takes the
  same claim route.
- **An older copy of `wf` runs the installed one.** A `bin/wf` older than the release `wf install` linked into
  `~/.local/bin` runs that release instead. It passes its exit code and signals through and prints a note on stderr.
  These run as they are:
  - the same or a newer copy;
  - a copy run with `WF_NO_FORWARD=1`;
  - `wf install`, so an older release can still be installed to roll back. An owner session had copied the 0.7.12 engine into a temporary folder
  to use it early, and ran that copy for two days and six releases.
- **Agents run `wf` from their PATH and never change the workflow from a ticket.** The AGENTS.md block and the work skill
  say so. When `wf` refuses and names no route, the agent says so and records it with `wf improve add`.
