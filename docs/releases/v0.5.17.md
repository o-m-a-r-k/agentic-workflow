## 0.5.17 - Host-compatible roles and review closure

- I-75: reviewers can write the completed closure with Claude Write, a supported Codex Node `fs.writeFile`, or native `apply_patch` targeting only the handed closure path. Missing Claude tools no longer stop a Codex review. Source and evidence edits remain prohibited.
- Shared role instructions now explain supported text, skill and image tools. Codex uses the complete-output Node protocol or the permitted `wf evidence show` reader for frozen documents, and `view_image` on exported screenshot copies. Required inspection, full-document receipts, screenshot coverage and verdict obligations remain unchanged.
- Completed direct and functions-exec `exec_command` reads now earn document receipts only when a literal permitted command delivers the actual full file contents in successful output. Failed, partial, running, conditional and wrong-path calls remain rejected.
- Work, quick-fix and resume skills consistently use fresh engine-launched Codex handoffs. They no longer require Claude messaging tools or a parent-session restart for native role instructions. Finished native processes cannot be messaged or reused as fresh roles.

Regression scenarios cover generated Claude/Codex agents, owner skills, native launch instructions, a process that writes and records its own review closure, command receipt transports and rejected reads. The evidence guard and existing review-tree protections are unchanged. Existing frozen launch receipts remain historical records; use a fresh handoff from the updated engine to receive the corrected instructions.
