## 0.7.3 - Confirm reserved decisions from the question panel; a shell can leave the evidence folder

- I-106 (D12): `wf approve` needed the person's own terminal, so from the phone they could confirm nothing, and a
  ticket stopped until they reached the machine. Now the agent may ask them in its question panel and run
  `wf approve <id> --from-question`: the engine reads the answer the harness recorded (Claude Code's `AskUserQuestion`
  answers, Codex's `request_user_input` reply bound to its call). The answer counts only when the question names the
  attempt and the decision and carries the decision's summary, offers exactly its choices, and was answered after the
  decision was created; the person's chat prose, sub-agents, other sessions and non-interactive `codex exec` runs are
  never read. Every refusal that opens a decision prints the exact question and options to ask. The decision records
  the channel (`question-panel (<harness>, host-recorded)`), and a deferral it confirmed says so in the delivery output
  and the delivered comment. Typing `wf approve <id>` at a terminal works as before.
- I-105: an agent that ran `cd` into the evidence folder (shell text is not scanned, so it passed) left its shell
  standing there, and the guard then refused every command, `cd` out included: the session could run nothing. From
  inside the evidence folder a bare `cd` to a folder outside it now passes; every other command there is still refused,
  and the refusal says how to leave.
- Align the CLI package and both host plugin manifests at 0.7.3.

Regression scenarios: `scenarios/approve-question.test.mjs` (the field case, adopting a live owner's attempt, confirmed
in the question panel on Claude Code and Codex, and every way an answer must not count) and
`scenarios/guard-regressions.test.mjs` (a shell inside the evidence leaves with a bare `cd`; nothing else runs there).
