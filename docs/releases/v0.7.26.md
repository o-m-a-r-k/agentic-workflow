## 0.7.26 - A moved base reaches a delivery waiting on a merge request; a ticket's handoff shows its own screenshots

- **A base that moved while a merge request waits can be brought in (I-183).** With a delivery adapter whose merge a
  person makes (a merge request), the base branch moved after the first `wf deliver`. `wf base merge` refused ("already
  being delivered"), and every later `wf deliver` only checked the merge request again, so the branch stayed behind the
  base and the merge request could not be merged as reviewed. Now:
  - `wf base merge` brings the base into every repo still to deliver. A repo already delivered, or skipped, or whose
    change is already on its target, is left as it is.
  - **One rule for adapters (D31):** a base merge on an accepted attempt whose delivery goes through an adapter
    withdraws the acceptance, whether or not a delivery has started. The gate runs on the combined code, then the
    evidence review (or a code review first when the base touched the ticket's own lines), then `wf accept`. The next
    `wf deliver` hands the reconciled branch to the adapter again, and the person's merge of it is recognised.
  - Built-in push-main keeps its own behaviour: the acceptance stands, and once delivery started `wf deliver` merges the
    base itself.
  - A review round still covers the change when only the base moved: repos already delivered are not compared, so a base
    merge that leaves the ticket's lines alone asks no new code review (the person's rule: no rerun that adds nothing).
  - `wf deliver`, while it waits, says when the base moved meanwhile, and `wf resume` names the evidence review after the
    gate on a moved tree.
- **A ticket's handoff shows its own screenshots (I-182, D32).** After a combined delivery, each ticket's handoff held
  only the screenshots tagged for every ticket, and none of its own. The cause was not a cap: a capture tagged with the
  ticket's item id was never matched, only its attempt id. Now each handoff draws from every verified capture:
  - captures a criterion of the ticket cites come first, then the ticket's own, then shared ones; captures tagged only
    for other tickets stay out. Nothing is cut at a number.
  - `wf delivery list` shows every verified capture, its place, and whether it is in the set; `wf delivery narrow` can
    add any verified capture, not only one already in the set.
