## 0.7.20 - Every screenshot exports

- **`wf export screenshots` writes every record when names clash.** Two test suites captured screenshots at the same
  relative path, so their titles flattened to one file name. The whole export was refused, and a reviewer could open none
  of 422 screenshots. Now:
  - every screenshot has a title unique in its set: the file name; the source path when two share a name; the gate
    step that captured it when two steps captured the same source path; a number last. Delivery uploads and the tracker
    readback match each record by its own title;
  - a record whose file name is already taken in the export folder is written with a number (`home-2.png`), each checked
    against its sha256, and the output names the title beside a numbered file;
  - the filesystem decides what is taken, so names it folds together (different case, Unicode forms) are numbered too;
  - an entry this export did not write (a planted link or file) is still refused and never followed or replaced.

  An owner session had patched its own copy of the engine to get past this. 0.7.19 makes such copies run the installed
  release, and the work skill says to report a refusal with no route instead of changing the workflow.
