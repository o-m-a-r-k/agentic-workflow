## 0.7.24 - An abandoned combined delivery releases its parts

- **Abandoning an assembled batch releases its members (I-181).** Before, each member kept pointing at the abandoned batch.
  It could then be neither delivered alone, ejected (the batch's worktree was gone) nor batched again, so finished work was
  stuck. Now `wf abandon` on a batch records each member as leaving it, so it can be combined again (`wf batch create`;
  `wf resume` says so for a member whose heavy steps were deferred to a batch).
  - **An item a member handed to the batch to fix comes back to the member** (the 0.7.23 route for a fix asked after the
    parts were combined), still open, so the member cannot ship without it.
  - **Members a split put together** (so that they ship together) leave only on the person's decision: one question for
    the batch, in the 0.7.23 question shape. Nothing is released before the answer.
  - **A member left behind by a batch abandoned before 0.7.24** leaves it with `wf batch eject --batch <id> --member <id>`.
    Its own record changes; the batch, closed, is not rebuilt.
- **The workflow writes nothing into a project's AGENTS.md (D30).** Its standing rules reach every session from the plugin
  itself, with the project's lanes, tracker, delivery and invariants from its `.workflow/` adapter:
  - **Main sessions:** a SessionStart hook. Measured: a Claude Code session and a Codex session each quoted the rules word
    for word, and neither did without the hook.
  - **Subagents:** a SubagentStart hook. Measured on Claude Code: a subagent sees the project's instruction files but not
    its session's start-up context, so without this hook it had no rules; with it, it quoted them.
  - **Workflow roles:** every role bundle carries the rules (`workflowRules`), whatever the harness and whether or not a
    hook has been trusted.

  Outside an enabled project the hooks give nothing. `wf sync`, `wf enable` and `wf disable` remove the block earlier
  releases wrote into `AGENTS.md`. Only the block and the blank lines around it change: the project's own text keeps every
  byte, line endings included, and markers quoted inside a code fence are left alone. `wf status` names a tracked file that
  still has one.
  - Named failure: the block put the plugin's text into each project's own instruction file, so a plugin release that
    changed it meant a commit in every project. The person: "this is part of the workflow plugin or adapter setup. not
    agents.md".
  - **After installing:** run `wf sync` in each project and commit the removal of the block. Codex may ask once to trust
    the new hook.
