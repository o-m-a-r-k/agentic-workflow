## 0.7.14 - The person's rules reach the agents

The person's rules on test runs and gates were kept in a maintainer's notes rather than in the texts the agents read. One
implementer spent 266 minutes on a 90-minute estimate: 201 of them in sleep loops waiting for its own background runs of a
573-test end-to-end spec, run under load it added itself, after 20 and 30 targeted repeats had already proven its two fixes
(D24).

- **Implementers:**
  - Confirming a cause means the failing tests alone (repeated when intermittent). A whole spec file, a full end-to-end
    run or a repeated typecheck is the gate's run, never theirs, in every round. So is any run under load they add
    themselves.
  - A failure seen only on a loaded machine is reported as that, not chased.
  - They never wait on their own runs in sleep loops.
  - A failure in files they did not touch is reproduced on a clean base first, then fixed anyway.
  - Tests only for an invariant or a regression no existing test catches; no tests of source text.
  - No backticks or `${}` inside double-quoted shell arguments.
- **Owners:**
  - A role past its estimate is judged by what it is running, not by whether it is active.
  - Before the gate, a moved base is merged and the failures already known on it are fixed.
  - The person's scope words are taken literally.
  - Items left as follow-up work go into one ticket.
- **`wf signals`** shows, for each working role, the shell command it is running now and the time it spent in commands
  of 5 minutes or more, with the longest. The owner sees "208 min in 23 commands; longest: a sleep loop" while it
  happens.
- **Plugin updates reach running sessions without a restart.** When a role's file changed after the owner's session
  started (a plugin update), the handoff says to launch that role with `wf handoff run`, a fresh process that reads the
  current file, instead of starting it by agent type. `wf sync` no longer asks for restarts.
- **Planners:** a contract names shared test helpers and fixtures; work items that edit one hub file run in sequence.
- **Reviewers:** a skill the project requires is applied to the evidence it covers, not only named.
- **Plugin development:**
  - A rule the person gives lives in the texts agents read.
  - Experience reviews run on the strongest model, briefed with the threat model.
  - Nothing reruns that cannot add information.
  - A maintainer release goes to main after a green verify, with no pull request.
