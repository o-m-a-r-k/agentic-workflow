## 0.7.5 - Close an attempt that shipped outside the workflow

- I-116 (D16): an attempt whose change reached its target branches by another route before its acceptance (one repo
  delivered, the others merged by hand) could be neither abandoned nor delivered, so it stayed ORPHANED in every listing.
  `wf close --shipped --reason "<why>"` closes it: the engine checks in each repo's own checkout that every recorded change
  (the delivered commit, else the head the last gate ran on, else the accepted head, else the worktree's HEAD) is on its
  remote target branch, and refuses naming any repo whose change is not; closing without the acceptance is the person's
  decision (`wf approve`, kind `override-gate`, which also ends a hold). The ledger keeps the commits, the decision and what
  was still open; the worktrees are removed; the tracker is not touched.
- `wf abandon` of an orphaned attempt now refuses when a repo's recorded change is already on its target branch, as it did
  for a worktree that exists: a change that landed is never recorded as given up.
- Align the CLI package and both host plugin manifests at 0.7.5.

Regression scenarios: `scenarios/close-shipped.test.mjs` (the field case over a hold, a change not on its target branch,
and what was open recorded with the close); each fails on 0.7.4.
