## v0.5.2

Adoption accepts a combined human command such as "Read HANDOVER-ENG-1.md and then adopt ENG-1.1" (I-33). The adoption command no longer needs to open the message. Quoted examples, reports, negations and conditional requests refuse; other owner decisions retain their exact phrases. Refusal diagnostics describe the actual adoption requirement.

Codex transcript discovery follows the active rollout in the host's thread index (I-34). Desktop resumes can write suffixed rollout filenames while retaining an older initial rollout; filename-only lookup previously missed new human requests. The engine opens the index read-only, validates the selected file inside the host transcript folders, and cross-checks its session metadata. It never selects a transcript by modification time or substitutes an older file when an index entry is invalid. Older hosts without an index retain unique unsuffixed-file discovery. Node with built-in SQLite reads the index directly; Node 20 uses a read-only system sqlite3 or Python 3 reader.

Scenarios reproduce both failures and verify unchanged interactive human authority, one-use receipts, holds and work preservation, and refusal of wrong-thread, missing, linked, corrupt and out-of-store records. The system-reader fallback is tested with built-in SQLite disabled.
