## 0.5.3 — Codex runtime integration

- **Owner handoff closure (I-35):** Codex can close a completed implementer from its own exact direct or literal functions-exec shell call. Child/headless, stale/future, replayed, forged-result and ambiguous-script records refuse; human authority remains required for every other owner decision.
- **Runtime-specific model checks (I-36):** doctor checks the current runtime, or `--runtime claude|codex`. Claude pins cannot conceal missing Codex planner/reviewer pins; model and effort strings remain open.
- **Installed Codex skills (I-37):** find skills from native installed/enabled plugin versions, including namespaced skills; cached or disabled copies do not count.
- **Usage totals (I-38):** read the active indexed rollout and native thread snapshots. Cached input and reasoning output are counted once; retained copies are not summed.
- **Planner runtime isolation (I-39):** a Codex handoff never imports an unrelated same-named Claude transcript.
- **Connector receipts (I-40):** native Linear tool aliases and single literal functions-exec calls with unchanged native output support host-recorded tracker readback; ambiguous code and changed/error output refuse.
- **Verifiable fresh Codex roles (I-41):** `wf handoff run --agent <id> --attempt <id>` launches an existing Codex handoff through the native CLI using the frozen start line, trusted role instructions and configured model/effort. Protected launch records bind the returned session id; the actual host prompt must match. Plans import unchanged from the completed role; reviews retain tree binding and all acceptance and document-read checks. Existing encrypted desktop spawn histories remain unverified and cannot be upgraded retroactively.

The native launch uses the workspace-write sandbox and does not bypass platform approval or inherit the parent conversation. A failed launch needs a fresh handoff. Codex cumulative usage across model switches remains a cost estimate, and desktop handoffs without a recorded session id lack per-agent usage.
