## 0.6.0 - Flow-aware parallel review pilot

- Opt-in `--parallel` reviewer handoffs and foreground advancement divide large changes into two or three complete
  flow areas plus independent integration. Recorded producer, consumer, contract and suite relationships determine
  ownership; repeated feature actions coalesce, shared/unmapped code belongs to integration, and changed-line cost
  estimates balance whole areas. Small, ambiguous, mostly shared or highly unbalanced changes retain one reviewer.
- Immutable scoped reports cannot authorize a gate or acceptance. Integration directly checks crossing interfaces
  and global obligations, cites every exact report hash, and the engine unions all findings and owned verdicts.
  Missing coverage, omitted reports, altered inputs, stale trees/obligations and superseded reviewers are refused.
  All participants retain the frozen reviewer class, runtime, execution settings and required documents.
- Current impact catalogs replace repeated amendment payloads in grouped handoffs; complete history remains
  immutable and hash-referenced. Snapshot-local query results are reused while preparing a handoff; closure recording
  still independently reruns the queries. No obligation or earlier-round finding is waived by compaction or division.
- Short evidence transactions serialize raw report capture, ledger/manifest registration and readers, fixing a race
  reproduced by concurrent native review fixtures on Linux. Locks never expire live or uncertain owners by age.
- Newly created workflow state roots receive the macOS file-provider ignore attribute before children or payloads,
  preventing the unmarked creation window seen with cloud conflict copies. Missing Git patterns go to local
  `info/exclude`; doctor warns about numbered/UUID siblings and empty evidence with populated copies. Existing
  synced folders and conflict copies are preserved. The Apple attribute is undocumented; see the state-folder guide.
- Group status reports every member. Failed/unknown launches stop advancement, preserve evidence and require
  diagnosis; there are no silent retries or duplicate runtime launches. Existing single-review rounds are unchanged.

The parallel-review guide documents commands, ownership, evidence and evaluation. Scenario tests cover native
concurrency/provenance, complete code and evidence review, blocking findings, unsafe division paths and existing
security guards. Real model speed and defect recall remain to be benchmarked before enabling parallel review by default.
