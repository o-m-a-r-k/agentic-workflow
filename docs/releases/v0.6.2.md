## 0.6.2 - Automatic review defaults with lazy cost scans

Fresh reviewer handoffs and foreground advancement automatically select scoped flow reviews plus integration for
large, separable changes. Small, ambiguous, mostly shared or highly unbalanced changes retain one reviewer;
`--single` explicitly keeps one reviewer for fresh rounds. Existing handoffs keep their recorded assignments.

- Single-review fallback skips unnecessary Git cost scans. Parallel candidates calculate changed-line weights once
  when needed, preserving cost balancing and expensive-flow fallback without adding that work to small reviews.
- GitHub's macOS job isolates scenario files to reduce fixture contention around the existing strict stop-process
  deadline. Timeout diagnostics identify the stage consuming the budget. Every scenario and its original assertions
  and deadline remain; concurrent runner/reviewer checks still execute their own parallel processes.
- Both host manifests and the CLI use a fresh version so clients that cached the preceding main-branch version
  receive the completed repair. Historical plugin cache paths remain valid for ongoing sessions.

Regression scenarios prove ordinary and foreground automatic selection, the single override, complete scoped and
integration coverage, lazy cost evaluation and original stop-process behavior. Real model speed and defect recall
remain unbenchmarked.
