## v0.4.5

- **Security fix: only the owner defers a discovered issue, as the host recorded it.** In 0.4.4, `wf discovered close --deferred` refused a deferral only when the caller-typed `--by` named a role agent. An agent that left `--by` out could defer with words it made up.
  - **A fixed phrase, host-recorded.** The owner starts a message in the owner session with `defer <attempt id>:<issue id>` (for example `defer ENG-1.1:D3`), optionally `: <reason>`; `wf discovered list` prints the phrase. Then `wf discovered close D3 --deferred` takes the decision from exactly one owner turn that starts with it. The turn must lie after an anchor recorded when the entry was added (the transcript's size and the sha256 of its bytes, which must be unchanged). The whole turn is recorded with its file, line, offset and anchor. No natural-language intent is judged: "D3 can't wait" or "Don't defer D3" are refused because they do not start with the phrase. `--decision` and `--quote` are refused, and `--by` is attribution only.
  - **At an interactive terminal.** `wf discovered defer <id> --reason "..."` runs only at an interactive terminal and asks for the id to be typed. Ending the input (Ctrl-D) or typing anything else refuses, and nothing is recorded. It is recorded `interactive-terminal (unverified)`: the Bash tool of an agent runtime has no terminal, but a pseudo-terminal wrapper gives it one. As a speed bump, the evidence guard refuses an invocation of `wf discovered defer` or `close` that is not one plain command. It triggers on `discovered` followed anywhere by `defer` or `close`, with quotes and backslashes dropped. It matches raw text only, and nothing is tokenised or unquoted. The plain command may hold no `; & | ` + '`' + ` $ ( ) < >` or backslash. Any other command naming it is refused when it carries such a character or a wrapper, interpreter or indirection word (`script`, `expect`, `bash`, `sh`, `eval`, `base64`, `xargs`, `python`, `node` ...). A commit message that only mentions it passes. The refusal says how to avoid it: run the command on its own, or put such text in a file (`git commit -F <file>`).
  - **Acknowledged at delivery.** `wf deliver` refuses while a deferral is unacknowledged. It lists each one with its id, summary, the owner's recorded words, the channel and its verification level. `wf deliver --acknowledge-deferrals D2,D3` (batch members' as `<attempt>:D2`) delivers. The acknowledgement is recorded only after every other check has passed, so a refused delivery is retried with the same command. The delivery output (every batch member's too) and the delivered comment's known limits list each deferral with its attempt-qualified id, the owner's words, the channel and its acknowledgement.
  - These never count: tool results; meta lines; compaction summaries; lines the host marks as not from the person (`origin.kind` or `turnOrigin` other than `human`: task notifications, messages relayed from other agents, scheduled prompts); turns that are a host or runtime wrapper (`<scheduled-task>`, which this host records with origin human, `<task-notification>`, `<system-reminder>`, relayed and cross-session messages, hook and command output, Slack wake-ups, Codex environment, AGENTS.md, subagent-notification, heartbeat and shell-command blocks); assistant text; and subagent transcripts. Anything else written into the transcript as a plain user turn counts. Two turns with the phrase are refused as ambiguous. `wf discovered add` says at once when an entry gets no transcript anchor.
  - `wf deliver` prints every deferral verbatim with its source. The reviewer bundle carries the same text.
  - **Limits, plainly.** The plugin does not defend against an adversarial agent with your user's tools. Such an agent can edit the transcript after the anchor, answer the terminal prompt through a pseudo-terminal, and acknowledge at delivery. These controls are speed bumps plus audit visibility: every deferral is recorded, shown at delivery and in the delivered comment, and named with its channel.
- **The evidence guard says what matched and how to avoid it (I-16).**
  - The refusal names the token that matched, or the working directory for a command run inside the evidence. It says how to avoid the refusal: write "the evidence folder" in commit messages, echo text and grep patterns; read evidence with the Read tool or `wf evidence`; copy screenshots out with `wf export screenshots`; run each `wf` command as one plain invocation.
  - Nothing that was refused before passes now. The guard still decides on the raw text and never parses shell.
  - **Security fix.** `wf run --lease X -- <command>` executes its command but was treated as a plain `wf` invocation. A command on the evidence wrapped in it went through. It is now judged like any other command.
- **`wf evidence list [--kind K]` and `wf evidence show <path>`.**
  - `list` gives an attempt's evidence files by kind (gate logs, records, plans, handoffs, reviews, tracker, delivery, screenshots), with relative and full paths. `show` prints a text file.
  - Both write nothing of their own; opening the attempt runs the usual verification. A link at the attempt folder or at a file is refused. `show` reads at most 4 MiB and refuses paths outside the attempt, binaries and images; for images it points to `wf export screenshots`.
  - The reviewer, implementer and work-skill texts use them, so no shell command needs the folder's name.
