## 0.7.1 - A decision taken on an orphaned attempt is reported as taken

- I-103: `wf approve` on an attempt whose worktree folder is gone recorded the person's choice, then failed with
  "worktree missing: ... (git was not run there)" while printing the next step, so the decision read as not taken;
  `wf release` did the same after lifting a hold. The orphan check now sits in `nextDecision`, where every next line
  is decided, before any git call: every command reports an orphaned attempt's next step as ORPHANED with its missing
  paths and the `wf abandon` command, as `wf status` and `wf resume` already did. `wf advance` stops on it as blocked.
- Align the CLI package and both host plugin manifests at 0.7.1.

Regression scenario: `scenarios/dead-ends.test.mjs` lifts a hold on an orphaned attempt through `wf release` and checks
its next line and the `nextAction` line that `wf approve` prints after recording a choice; it fails on 0.7.0 with the
field error.
