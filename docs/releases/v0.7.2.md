## 0.7.2 - wf run inside the adapter repo works on the project

- I-104: a multi-repo project keeps its adapter in one repo and links the project's `.workflow` to it (the layout
  `wf init` makes). Run from any folder inside that repo, `wf` stopped at the repo's own `.workflow/` and took the repo
  for the project: `wf status` listed no open attempts while the project had one, and `wf doctor` and `wf entry` failed
  with "`.workflow/` is not inside any listed repo". The search for the project root now goes on past the adapter it
  finds: a folder above whose `.workflow` link leads to that same adapter is the project.
- Align the CLI package and both host plugin manifests at 0.7.2.

Regression scenario: `scenarios/delivery.test.mjs` admits an attempt from inside the adapter repo of a two-repo
project and runs `wf status` and `wf doctor` from each repo, a subfolder and the attempt's worktree; it fails on 0.7.1
with "no open attempts".
