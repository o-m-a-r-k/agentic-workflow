## 0.7.27 - Causes, not places; questions asked once; tickets routed by label

- **Your answer in your own words counts (I-192, D41).** Named failure: you told the agent "ok we can close this then.
  ticket is on done? and clean up completed?" and the workflow refused it, because the agent's message before it had
  described the closure in its own words instead of quoting the question, the two follow-up questions made the whole
  reply read as a question back, and "close this" was not a name the engine knew (the question had been created by an
  older release, with no words of its own). The agent then stopped without asking anything, and later refused "close
  the ticket (mark done)". Now:
  - a reply that names what the question decides, in your own words ("close this", "go ahead and close", "close the
    ticket", "lift the pause"), counts whatever the message before it said, when it is your words in the session's
    record, after the question existed, and no other open question fits the same words; a reply that negates it,
    makes it wait on something ("close it after the review", "if all good, close it"), asks about it ("should we
    close it?") or names another option counts for nothing, and your latest words about it decide;
  - a reply is read sentence by sentence, so a question about something else ("is the ticket done?") no longer turns
    a clear answer into a question back; a request in a question's form ("can you close it?") is a request;
  - a question an older release created gets the words of its kind of question, read from what it is;
  - generic words ("continue", "stop", "keep it") and escalations still count only in reply to a message that asked
    or named the question, and a reply that names nothing of a question and shares no word with it ("where are we?
    update the wf plugin") is no answer to it;
  - Codex Desktop's note of the page open beside the chat is no longer read as your turn, so your reply the next day
    answers the question asked the day before; a message you type while the agent works counts as yours;
  - agents ask a pending question in the form that binds, in any reply that mentions it, and never end a turn on a
    refused answer without asking it; `wf status` and `wf resume` list each unanswered question with that form.
- **Done when you ask for it.** The workflow never moves a ticket to Done on its own initiative; a ticket goes there when
  the project's routing sends it (`tracker.statusByLabel`), or when you explicitly ask for it in the conversation, and
  then the agent does it.
- **`wf improve` says when a fix is not out yet (I-193).** `wf improve list` and `show` add "not released or installed
  yet" beside a fix in a release newer than the running wf.
- **A fix round's goal is that no review finds the problem again anywhere (I-191, D36).** Named failure: a ticket ran ten
  and more review rounds where each found the next place one wrong assumption lived (six places), because every role
  worked one finding at a time: a fix round was handed only the latest finding, and a delta reviewer judged whether a fix
  held where it showed up. Now:
  - a fix round's bundle carries the ticket's finding history (each finding, where it stands, the fix recorded for it),
    and its goal is to name the assumption behind each finding, find every place that relies on it, and fix them all;
  - a reviewer judges the cause, not the place: a fix that holds where the problem showed up while the cause lives
    elsewhere stays open, naming where else, and a new finding that shares the cause of an earlier one says so
    (`sameCauseAs`);
  - when a cause comes back, `wf resume`, `wf status`, `wf signals` and the strategist say so plainly ("the cause of
    r9:F1 came back in r10:F1: the last fix covered one place"), also when a finding marked fixed is found open again,
    and a finding with the family of one marked fixed is flagged as a possible recurrence (a label match, apart from a
    cause a reviewer confirmed). A `sameCauseAs` that names nothing is dropped and the receipt says which; it is never
    a refusal. Information, not a stop.
- **The person's review-round limit stops every ticket (I-185, D34).** An attempt admitted by an older release ran 14
  rounds and the "how should it go on" question never opened. The person's stops now apply to every ticket still worked,
  whichever release admitted it. A ticket already past the limit asks at its next handoff. `wf signals` no longer reads
  "0 blocking" while earlier rounds' blocking findings are still open: it counts what is open now, new and carried
  (per round: of the first N rounds' findings, open now).
- **A withdrawn strategist question no longer blocks the strategist's corrected decision (I-186, D33).** The corrected
  decision supersedes it; until then the withdrawn question still holds the work, and `wf resume` names the way on. When
  the round question is due as well, the waiting strategist is named beside it, and the withdrawn question is not asked
  afresh while a strategist handed after it has not decided (the person is not asked the same stop twice); with none handed since, the next step says to hand one and record its
  decision first, and the handoff that asks the withdrawn question again as it was names the way out.
- **Never asked twice, continued (I-187, D37).** An approved correction of an admission check holds across a base merge
  that leaves the corrected steps unchanged; it is keyed by what it changes, not by the commit. A question an earlier
  release asked under its commit is the same question while those steps are unchanged.
- **"Not a defect" (I-188, D38).** A discovered issue raised on a wrong premise closes as `not-a-defect`, keeping its
  claim and the reason: by an independent reviewer's verdict (`verified-nonissue`, with evidence and rationale), or by the
  person's decision (`wf discovered close <id> --not-a-defect --reason "..."`, one question per item). It is not listed
  as a known issue. The next reviewer is told which of the three closed it.
- **A left item that names an existing issue is that issue (I-184, D35).** An implementer report's `left` item with
  `discoveredId` links to the issue instead of creating a duplicate.
- **Tracker statuses routed by label (I-190, D39).** `tracker.statusByLabel: { <step>: { "<label>": "<status>" } }`
  routes a ticket's status by the ticket's labels (for example, tickets with one label go to Done on delivery). The
  status asked for comes from the latest readback recorded so far; the readback that proves it is judged by its own
  labels, so a label taken off before delivery routes nothing, and the route used is recorded (in the state and the
  export). A tracker the engine performs itself routes at the seam, for built-in and project adapters alike: it reads the ticket
  through the adapter's `perform` with no actions, takes the labels that readback reports, and hands `perform` the status
  to set, so an adapter carries no routing rule and none can set a status its own readback refuses (an adapter's
  `perform` with an empty `actions` list must only read, and the note when that read fails says so). A rule for
  `started` routes at admission too: the engine reads the labels before it sets the status, and through a connector the
  pending action names the routes (the admission readback is judged by its labels); `wf doctor` says which applies.
  Nothing sets Done unless the project's setup routes it there (the person's choice in the adapter) or the person asks.
- **Trackers that attach screenshots (I-189 plugin side, D40).** A tracker adapter may declare `screenshots:
  'attachments'` or `'attachments-only'`: the delivered comment lists the files instead of embedding images, and delivery
  is checked against the readback's uploaded attachments by file name, each carrying the owner's caption as its
  subtitle in both modes (an agent-reported attachment also names its upload by an https `assetUrl`). An attempt keeps
  the tracker adapter committed at its admission, so a `screenshots` declared later applies to the attempts admitted
  after the adapter commit; an attempt already running keeps embedding.
