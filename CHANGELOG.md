# Changelog

Release notes, newest first, then every fix that came from a failure in the workflow itself. Generated by `node scripts/changelog.mjs` from `docs/releases/` and `improvements/`.

## v0.4.3

- **Every handoff names the agent to start (I-14).** `wf handoff reviewer` now prints `Start agent type wf-reviewer (name it <id>; do not pass a model)` on stderr; stdout is still only the one start line. Before, a reviewer started without a name did the whole review and then had its closure refused. `wf review` and `wf plan --from-agent` now accept an unnamed agent when its identity is unambiguous: exactly one unnamed transcript of the handed agent type began with this handoff's own line, after the handoff. It is recorded `identity: unnamed`. Zero matches, several matches or another agent type are refused, and the refusal says how to start the agent: its type, its name and only the printed line.
- **Role changes and running sessions (I-15).**
  - `wf sync` rewrites a role file only when its content changed. It lists the changed role files and says that a session already running keeps the roles it loaded.
  - `wf handoff` warns when the agent type's role file changed after the owning Claude Code session started. The start is the later of the transcript's first entry and the process start, so a resumed session is not flagged.
- **Lessons match the change's declared scope.**
  - A lesson declares `repo`, `components`, `paths` and `kinds` (ui, test, migration, docs, script, config, source). It reaches a bundle only when a changed or planned file satisfies all of them, or when the ticket mentions one of its tags.
  - A lesson whose repo was admitted to the attempt but not changed is no longer handed to the reviewer. A project lesson with no scope no longer applies to every change; `paths: ["**"]` says so explicitly, and `wf lesson list` warns about lessons without a scope.
  - Handoffs print the filtered ids, and the ledger records them. `wf lesson preview` gives the reason for each filtered lesson. Filtered lessons never enter a bundle, so they owe no verdict and no trailer.

## v0.4.2

- **Connector handoffs reach verified evidence.** `wf tracker record --event E --from-transcript` reads the attempt owner's Claude Code or Codex transcript, which the host writes. It takes the tracker's own get-issue and list-comments results recorded after the event and runs the raw-capture checks on them. It also records what the session posted. It is recorded `host-recorded`, distinct from `engine-read` (api, cli, files) and `agent-reported`. Limit: a same-user process could edit the transcript.
- **Agent-reported fallback.** `--agent-reported --file reported.json --comment-file posted.md` is for connector mode where no host record exists. The engine checks the item, the status, the comment text (its sha256, the fixed lines, the summary, an image per screenshot, no internals), the captions and a fresh read time. It is recorded `agent-reported, unverified` and shown so in status, export and the closing message.
- **Security fix from review (credential exfiltration).**
  - Tracker error notes are scrubbed of the key and of anything token-shaped (Authorization or Bearer values, known token prefixes, signed-URL signatures); a fetch error's request is never shown.
  - `gh` runs with a minimal environment, so no other service key of the owner reaches it.
  - Exports (HTML and JSON) mask signed-URL signatures and tokens on top of the catalogued secrets.
  - From a transcript, only the matched tool results are kept: no other line reaches the evidence, and the scratch copies are removed.
  - Owner-added comment lines are recorded masked.
- **Owner additions to the delivered comment are allowed** when every rendered line is still there, in order. The added lines are listed in the record.
- **Wording.** `wf doctor` prints the readback level the current host reaches, the onboard skill states it, and the next step after delivery names `--from-transcript`.
- **Demo assets.**
  - The social preview shows whole lines of the real run: the gate refusal, the refused self-review, the delivery and the readback.
  - The demo SVG wraps long lines instead of cutting them off.
  - The generator refuses any line that would overflow.

## v0.4.1

- **Public screenshots on GitHub.** When the issues live in a public repository (or GitHub does not report its visibility), `wf doctor` prints `NOTICE: screenshots will be publicly downloadable`. `wf deliver` refuses to deliver a change with screenshots there until the owner chooses:
  - keep it, with `tracker.publicAssets: acknowledged` committed on the base branch;
  - switch to the files tracker;
  - keep the issues in a private repository.

  The adapter checks again before each upload. The onboard skill asks this question.
- **Docs.** The README is a short landing page. The reference moved to `docs/`: concepts, lifecycle, gate, delivery and tracker, onboarding, adapter schema, lessons, trust model and telemetry. A scenario checks that every relative link and heading resolves.
- **Corrections.** The docs no longer claim resource-peak sampling, which is not built. The tracker docs no longer describe a Linear-only setup.
- **Presentation.** This changelog, release notes per version, issue templates for bugs and plugin improvements, and a 1280×640 social preview in `docs/assets/`.

## v0.4.0

**Trackers.** `tracker.kind` (linear, github, files, none) and `tracker.via` (api, cli, files, connector) are chosen at onboarding and validated together; `wf doctor` states what is verifiable for the combination.
- GitHub Issues through your `gh` login (`via: cli`) or a `GITHUB_TOKEN` from `wf secrets` (`via: api`): status labels, the rendered comment, screenshots as release assets, read back by the engine.
- Tickets as markdown files in the repo (`kind: files`): the engine sets the status, appends the comment, copies captioned screenshots with their sha256 and reads it all back.
- `wf init` drafts the files tracker from a `tickets/` folder and names a GitHub origin.

**Security fixes from review.**
- Tracker tokens go only to endpoints committed in the adapter at the attempt's base, over https, never through a redirect; non-default hosts are named by `wf doctor`.
- One safe reader for every screenshot that is uploaded, copied or exported: no symlink, hard link, FIFO or path outside the evidence; the sha256 is checked on the bytes read.
- Files-tracker ticket ids and attachment names are validated before any file is touched.
- Input files that are symlinks (`--summary-file`, `--file`) are refused.

**Workflow.** The reviewer role gets the Write tool its instructions require, and `wf review` refuses a closure when the worktree changed during the round (I-13).

**Demo and CI.**
- `bash examples/hello-ticket/demo.sh` runs one ticket end to end; `node scripts/record-demo.mjs` re-records `docs/assets/` from a real run.
- `npm run verify` runs the suite on the host and in Linux as non-root and root, and the pre-push hook runs it; CI runs weekly too.
