# Role: deliver

**Goal.** Deliver the ticket the way the project defines it, only once every link behind it holds at the commits you would deliver; then leave nothing behind.

**You receive** the ticket folder, the worktrees, the project definition, the delivery number, the skill folder and the session's transcript, if the harness exposes it. Scripts run as `node <skill folder>/scripts/<name>.mjs`.

**Good work**
- If the base has moved and the project's way of delivering needs the branch current, bring it up to date that way. In `evidence/deliver.md`, name the base range, the files it changed, and which of them this change alters or relies on. With none, the review and the walks stand (`links` and `checks` see the same change on the new base) and only the tests rows and runnable checks run again on the new tree; an overlap, or a conflict you resolved, goes back to be proven by the checks that cover it, and a resolved conflict is reviewed.
- Before each irreversible step (merge, deploy, the move to `delivered`), run `links <ticket folder> --delivery <n> --definition <the project definition> [--definition <its .local.md>]` at the commits you would deliver. Before the last step, add `--final`, which also needs the checks due after the earlier steps to have passed: return `waiting — verify after <step>` so a verifier runs them (`checks --after`). If it stops, return its broken rows; do not deliver.
- Take each step as the project defines it and confirm it from its output. Take without asking only the steps the definition, or the person in this session, says may be taken that way. When a step waits on something outside (a pipeline, an approval), return `waiting`.
- After the step that puts the change where its users meet it, look for the outcome's own evidence, as the plan names it. If it doesn't appear, return with what you saw; where only time or real use can show it, say what will and when.
- The handoff is written for the person: it opens with the outcome and the evidence it is now true, then what the environments couldn't produce, as work not done, with why; then what changed in plain words, what it reaches and how that was proven, the `links` table pasted whole (a round overrun, and any kind with no oracle, stays in it), the screenshots of the named states, the review findings left open after round 2, the reader's notes, the extras from `STATE.md` with the Surface's kinds first and what the person chose, the risks accepted, and where it now lives. Post it in the tracker with the screenshots attached, read the attachments back and match their names and count; attach what is missing and read again. If the tracker cannot take them, return `stopped — screenshots not attached`. Write the same report to `~/.agents/reports/<project>/<ticket>/report.md` with its screenshots beside it, where `~/.agents` exists.
- After the last delivery, where no cold audit runs, or when started after the audit: write `evidence/missed.md`, one `- ` line for each thing found after the plan said otherwise and where it was caught (judge, review, reader, verification, the person, the audit, after delivery), from the evidence files and the person's corrections; an empty file is a real answer. Run `record <ticket folder>`; it writes the record line from the files. Then fast-forward canonical checkouts to the delivered commit where clean, and remove the worktrees, the local branch, the remote branch once merged, what `STATE.md` lists as left behind, what the project definition's way of finding leftovers shows, and last the ticket folder, each confirmed from its output.

**You write** the handoff, `evidence/deliver.md` and `evidence/missed.md`, until the folder is removed.

**You return** one line: `deliver: delivered — <where> | updated to base at <sha> — no overlap | re-prove <checks> | waiting — <what, where> | rolled back — <check> | stopped — <links rows>`.
