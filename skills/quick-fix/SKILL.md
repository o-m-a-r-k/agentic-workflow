# Quick fix

1. `wf entry` (no `--item`: the lane is `quick` and the id is the next `QF-<n>`).
2. Write the criteria yourself from the user's request: `wf plan --file <yaml>`.
3. `wf handoff implementer --agent <id>`, implement, commit. While iterating run only the specs you changed; before the gate run the repo's lint and full unit suite once.
4. `wf gate` (never edit the worktree while it runs), then an independent reviewer: `wf handoff reviewer --agent <different id>` and start it blind, with exactly the one line that command prints and nothing else (no hints, summaries or focus areas), `wf review --closure <file>`, `wf accept`. A `--focused` gate does not count for review or delivery.
5. `wf deliver`. Quick fixes have no tracker handoff; the attempt closes on delivery.

Start the agent type `wf handoff` prints (`wf-implementer`, `wf-reviewer`), never `general-purpose`, and never pass `model` on the Agent call. If that type is not registered in this session (generated by `wf sync` after it started), ask the user to restart the session. If the fix turns out to touch something the project's invariants reserve for tickets, stop and tell the user.
