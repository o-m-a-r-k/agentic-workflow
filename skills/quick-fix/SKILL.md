# Quick fix

A quick fix is small: one implementer, a handful of criteria, one review, one light gate (minutes, not hours). If it grows (the criteria keep multiplying, it crosses a shared component, an endpoint or a contract, or it touches something the project's invariants reserve for tickets), stop and tell the user it needs a ticket. Named failure: a "quick" fix that went from 8 to 45 criteria over 13 review rounds.

With more than one open attempt, pass `--attempt <id>` to every `wf` command. Never poll a running role: run it in the foreground or wait for the host's completion notification. If your harness cannot start an agent type by name, launch each handed role with `wf handoff run --agent <id> --attempt <id>`; native launches load fresh engine instructions.

1. `wf entry` (no `--item`: lane `quick`, id `QF-<n>`).
2. Write the criteria yourself from the user's request, with your own prediction of the fix (the engine refuses a plan that states none, and shows it beside what happens; it is not a limit): `wf plan --file <yaml>`. No planner, no impact analysis.

   ```yaml
   expect: { files: <n>, rounds: <n>, minutes: <n> }   # files touched, review rounds and minutes to delivery
   criteria:
     - { id: C1, text: What a person sees or can do when the fix is done., uat: How they check it. }
   ```
3. `wf handoff implementer --agent <id>`; start the agent type it prints, named as printed. It implements and commits; its goal is the criteria holding on the whole tree, with the repo's lint and unit suite passing (`wf check`) before the gate. When it reports done, `wf handoff close --agent <id>`.
4. `wf handoff reviewer --agent <new id>`; start it with exactly the line it prints. A finding blocks only if it fails a criterion, breaks a critical invariant or regresses a line the fix changed, and is rated medium or high (a finding rated low never opens a round); anything else is an observation. Severity is one scale: **high** = a user, a tenant or the business is harmed or blocked (wrong or lost data, a broken flow, security, money, a visible defect on a primary screen); **medium** = degraded but usable (a secondary flow, an edge case, a confusing state); **low** = polish (wording, spacing, naming, style); a tenant-isolation, authorization or money defect is always high. Place an observation in the same pass if it is trivial; otherwise the user's rule decides: medium and high (or unrated, or one that breaks a critical invariant) are fixed in this delivery, here or in a sibling attempt of the batch; a low one leaves only with the user's answer, one short question per item (`wf scope defer --finding <ref>[,<D-id>...]` for known issues, `wf scope ticket` for a follow-up ticket; give a plain line per item with `--explain <file.json>`), and they may fix one and let another go, or answer in their own words, which you then follow; the project's adapter may change who decides each level (`leaving:`); a fix that needs a product decision is a question for the user, not a deferral; a finding the user judges wrong is waived by them (`wf scope waive`). Fix blocking findings through the same implementer (`wf handoff implementer --agent <its id>`; each family answered by one mechanical proof in its report), then a fresh reviewer for a delta review of the new diff.
5. One `wf gate` on the reviewed tree: in a quick fix it runs the light steps only (lint, types, unit, build of what the fix touched, reused when unchanged), so it takes minutes; heavy steps such as end-to-end suites run only with `wf gate --full` (or always, when the project's adapter sets `gate.quickLane: full`), and a heavy step that failed in this attempt runs until it passes rather than being skipped. For a UI fix whose criteria need screenshots, capture them on the committed tree and bring them in with `wf captures import --from <folder>`. Then a fresh reviewer for the evidence review (gate logs and the screenshots not inspected before; a delta after a fix), then `wf accept`.
6. `wf deliver`. Quick fixes have no tracker handoff; the attempt closes on delivery. Show any screenshots in the chat with captions.
7. After the review and at delivery, `wf export --attempt <id>`; publish it as one private Artifact per attempt when the host has one, otherwise give the path.

If `wf resume` shows the course far from what was expected, or says `strategy`, the quick fix has outgrown itself: hand the strategist as the work skill describes, or stop and tell the user it is not a quick fix. Reserved decisions (waiving, ticketing or deferring a blocking finding, overriding a failed gate, lifting a hold) are the user's: ask them in your question panel with the question and options the refused command printed, then run `wf approve <id> --from-question --attempt <attempt>`. When the panel does not reach them, ask in your message instead (the question quoted exactly, its options, nothing else asked) and run the same command after their reply; or they run `wf approve <id> --attempt <attempt>` in their own terminal.
